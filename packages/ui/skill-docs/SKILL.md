# Documentation with jupiter-docs

Write documentation once, as Markdown in `docs-src/`. The `jupiter-docs` command (package `@belikh/jupiter-docs`, in this repo `packages/docs`) generates three outputs from it, so they cannot drift:

| Output | Where | Command |
| --- | --- | --- |
| Static site (docs.jupiter.au) | `dist/site` | `jupiter-docs build --site` |
| Plain GitHub Markdown | `docs/*.md` | `jupiter-docs build --md` |
| PDF | `dist/<id>.pdf` | `jupiter-docs build --pdf` |

**Never edit `docs/*.md`, `dist/site` or the PDF by hand.** Every generated Markdown file starts with a `Generated by jupiter-docs` comment; change its source in `docs-src/` and rebuild. Hand-written files in `docs/` that lack that comment (specs, status, notes) are not part of the system and are never touched.

The visual rules (type, colour, space, graphics) are in `DESIGN.md` in the `jupiter-design-system` skill. The generator already applies them to the site and the PDF, so you write content and leave the look alone. Do not add CSS, colours or images of your own to a docs page.

## Workflow

1. Edit or add a file in `docs-src/`. The file name is the page id (`guides/setup.md` is `guides/setup`).
2. `npm run docs:check` validates the source and names the file and line of every problem.
3. `npm run docs:build` writes `docs/*.md` and `dist/site`. Commit `docs-src/` and the regenerated `docs/*.md` together. CI runs `jupiter-docs build --check` and fails when a generated file is stale.
4. `jupiter-docs build --pdf` builds the PDF; it needs `xelatex` and `rsvg-convert`.
5. For a new project run `jupiter-docs init`, which creates `docs.config.json`, `docs-src/index.md` and a first page.

## Source format

`docs.config.json` (project root) holds `project`, `version` or `versionFrom`, `repo`, `siteUrl`, `base`, `sections` (in navigation order, each `{ id, title, summary, icon }`), `glossary` (term to definition) and `hero` (a spot graphic for the landing page). Unknown keys are errors.

Each page starts with a YAML block:

| Key | Meaning |
| --- | --- |
| `title` | Required. The page title (the body starts at `##`). |
| `summary` | Required. One sentence; shown under the title, in search and on cards. |
| `section` | Required except on `index.md`. An id from `sections`. |
| `order` | Number. Position in the section (default 100). |
| `icon` | A name from the icon tier of the graphics set, for example `home`. |
| `audience` | `users`, `developers`, `agents` or `maintainers`. |
| `status` | `draft`, `stable` or `deprecated`. |

Headings never skip a level. Raw HTML is an error: put literal `<tags>` in backticks.

## Directives

Block directives start with colons and end with a line of colons; use four colons for the outer block when nesting.

- `:::note`, `:::tip`, `:::warning`, `:::danger` with an optional title after the name: a callout.
- `:::see-also` containing a list of links: a "See also" block.
- `::graphic tier/name Alt text`: a graphic from `@belikh/jupiter-graphics`, for example `::graphic rule/end`. Alt text is optional; leave it out for decoration. Use a `rule` between major blocks and at most one `spot` or `scene` per page.
- `::glossary`: lists every glossary term (one page only).

Inline and link syntax:

- `[[page-id]]`, `[[page-id#anchor|link text]]`: a link to another page or heading. Relative links to `.md` files also resolve.
- `[[term:Name]]`: a glossary term that links to the glossary page.
- Code fences take a language and an optional title: ` ```sh title="Install" `. Always give a language; use `text` for plain output.
- Tables are plain Markdown tables with no merged cells. Keep cells short; put long text below the table.

## What each output looks like

- Site: the app's look from the tokens and components CSS, SGI fonts, light and dark, a left navigation by section, an on-page contents, previous and next links, search and a print style.
- `docs/*.md`: plain GitHub Markdown. Callouts become GitHub alerts, graphics become light/dark `<picture>` blocks, page links become relative `.md` links.
- PDF: `jupiter-docs.cls` in `packages/latex/src`, with a cover, running header, numbered sections and callout boxes.

## Add a graphic

Graphics come only from `@belikh/jupiter-graphics`: no emoji, no other icon sets, no screenshots as decoration. If the set lacks what you need, add it in `packages/graphics` first (see `jupiter-design-system`), run `npm run build:graphics`, then use its `tier/name`. `jupiter-docs check` fails on an unknown name.

## Writing rules

Same voice as the `github-readme` skill: plain words, short sentences, say what a thing does and then how to use it. No slogans, no "X, not Y", no filler openers or closers, no emoji, no comments about the document itself ("this page", "in this guide"). Headings are nouns or short verb phrases. Put install and run commands near the top. When a command, path or option changes, change the page in the same commit.

## Where things live

- `packages/docs`: the generator (`src/spec.mjs` lists every directive and header key; `src/cli.mjs` the commands).
- `docs-src` and `docs.config.json`: this repo's source. `docs/writing-documentation.md` is the full format reference.
- `packages/latex/src/jupiter-docs.cls`: the PDF class.
